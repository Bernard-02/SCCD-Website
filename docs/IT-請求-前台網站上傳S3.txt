──────────────────────────────────────────────
一、背景
──────────────────────────────────────────────
系上新版官方網站已開發完成，準備上線，取代目前 sccd.usc.edu.tw 上的舊 WordPress 網站。

・新網站是「純靜態網站」（只有 HTML / CSS / JavaScript）。
  不需要 PHP、不需要資料庫、不需要在伺服器安裝任何東西。
・經確認，sccd.usc.edu.tw 目前是由 Amazon S3 + CloudFront 提供靜態檔。
  （驗證方式：在終端機執行 curl -sI https://sccd.usc.edu.tw/
   會看到回應標頭 Server: AmazonS3、Via: ... (CloudFront)）
・我們手上沒有那個 S3 / CloudFront 帳號的權限，這部分需要 IT 協助操作。

──────────────────────────────────────────────
二、需要 IT 協助的事項
──────────────────────────────────────────────

【第一部分：上傳網站　←　做完這部分網站就上線了（必要）】

1. 我們會提供新網站的完整檔案（一個資料夾或 zip，全部是靜態檔）。

2. 請將這些檔案上傳到 sccd.usc.edu.tw 對應的 S3 bucket，
   覆蓋／取代裡面現有的「舊 WordPress 站」檔案。
   （建議先把舊站檔案備份一份再覆蓋，以策安全。）

   若使用 AWS CLI，指令大致如下：
       aws s3 sync <新網站資料夾> s3://<bucket 名稱> --delete
   （--delete 用意：把舊站殘留、新站沒有的檔案一併清掉。）

3. 上傳完成後，清一次 CloudFront 快取，讓新站立即生效：
       aws cloudfront create-invalidation --distribution-id <distribution ID> --paths "/*"

   ★ 完成以上三步，新網站即可正常瀏覽上線。


【第二部分：乾淨網址設定　←　選擇性，之後再做也可以】

新網站是單頁應用（SPA）。若希望網址呈現為
    sccd.usc.edu.tw/about
這種乾淨形式（而非 sccd.usc.edu.tw/pages/about.html），
需要在 CloudFront 加一條「SPA fallback」規則：

    CloudFront → 選該 distribution → Error pages（錯誤頁）→ 新增兩條：
        ・HTTP 403　→　Response page path: /index.html　，　HTTP Response code: 200
        ・HTTP 404　→　Response page path: /index.html　，　HTTP Response code: 200

    用意：讓找不到實體檔的網址都回傳 index.html，交由前端 JavaScript 處理頁面路由。

    ※ 這部分「不做」也能正常上線，只是網址會是 /pages/xxx.html 的形式。
    ※ 若要做，請在設定完成後通知我們，我們會同步在前端打開「乾淨網址」模式
      （兩邊要一起，順序是「先設 CloudFront、再由我們開前端」，否則直接輸入
       乾淨網址／重新整理會出現 404）。
