========================================
SCCD 網站 — 請 IT 修正 CloudFront CORS 設定
最後更新：2026-08-04
========================================

問題現象：
  前台影片縮圖截不出來（黑底佔位圖），瀏覽器 console 出現這種錯誤：

  Access to video at 'https://d2df28pyzslt2v.cloudfront.net/videos/xxx.mp4?sccdthumb=1'
  from origin 'https://xxx' has been blocked by CORS policy:
  No 'Access-Control-Allow-Origin' header is present on the requested resource.

  影片本身照樣能正常播放，只有「截圖當縮圖」這個功能會失敗。


原因：
  影片存在 S3 bucket（sccd-video-output-2026），S3 本身的 CORS 已經設好
  （Access-Control-Allow-Origin: *），但前台實際打的是 CloudFront 網址，不是 S3 原始網址。

  CloudFront 預設不會把瀏覽器的 Origin header 轉發給 S3 origin，所以 S3 收不到 Origin、
  不回 CORS header；CloudFront 又把這個「沒有 CORS header」的回應快取住，之後不管誰來要
  這個網址都會吃到同一份壞掉的快取。也就是說 S3 桶子的 CORS 設定不會透過 CloudFront 自動生效，
  CloudFront 這一層要另外設定。


請 IT 做兩件事：

1. 幫 CloudFront distribution（網域 d2df28pyzslt2v.cloudfront.net）掛一個
   Response Headers Policy，讓它在 edge 直接加上 CORS header：

     Access-Control-Allow-Origin: *

   做法：CloudFront Console → 該 distribution → Behaviors → 編輯對應的 cache behavior
   （路徑 /videos/* 或整個 distribution）→ Response headers policy 選用 AWS 內建的
   「CORS-With-Preflight-And-SecurityHeadersPolicy」，或自建一個只開
   Access-Control-Allow-Origin: * 的簡單版本。

   （這批影片是公開內容、不需要帶 cookie/credentials，用萬用字元 * 最簡單，
   不需要額外設定「轉發 Origin header + 依 Origin 分快取」那套更複雜的做法。）

2. 對已經被快取住的舊回應（沒有 CORS header 的那份）做一次 Invalidation，
   路徑填 /videos/* （或保險一點整個 /*），不然舊快取會照原本的 TTL 繼續回壞掉的版本，
   設定改了也要等 invalidate 完才會生效。


改完檢查：
  1. 瀏覽器打開 https://d2df28pyzslt2v.cloudfront.net/videos/任一支影片.mp4
     開 DevTools → Network → 該請求的 Response Headers 應該要看到
     Access-Control-Allow-Origin: *
  2. 回到網站任一個有這支影片的頁面，重新整理，縮圖應該正常截出來（不再是黑底）
