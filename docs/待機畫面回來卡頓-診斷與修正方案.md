> 「回到畫面」拆兩個情境，而且**通常連著發生**：切回分頁（A）→ 立刻動滑鼠喚醒（B），四段成本落在同一秒＝user 感受的「非常卡頓」。
> 關鍵背景：切回分頁**不會**自動退出待機——OS 補送的「座標沒變」mousemove 被刻意過濾（idle-standby.js:414-415，2026-06-28 決策），真的動滑鼠才退。

## 情境 A：切回分頁/視窗那一刻（待機畫面已掛著）

### A1.（CONFIRMED，主因）背景分頁 mount 的待機星雲，「首次繪製」全欠到切回那一幀
- 3 分鐘 timer 在背景分頁照樣 fire（idle-standby.js:403）→ `instant = document.hidden`（:313）→ **整份 atlas overlay 在分頁隱藏期間建好**（:333、:165-182；此為 2026-06-24 刻意設計「切回來時已經是待機」）。
- 隱藏分頁不跑 rendering pipeline → ~7500 節點的 style/layout/paint ＋ **431 顆 `will-change:transform` 合成層的建立、光柵化、GPU 上傳**（atlas.js:273 mount 即掛 `atlas-layered`；atlas.css:119）全部欠著，**切回可見的第一幀一次付清**＝巨幀。
- idle-standby.js 全檔無 visibilitychange 監聽＝沒有任何「切回時分攤」機制。
- **修法（ROI 最高）**：hidden 時不真 mount——instant 路徑只立旗標＋掛一次性 `visibilitychange→visible` listener，變可見後**下一幀**才 `mountStandbyAtlas(true)`。次選（改動更小）：照舊 mount 但 `atlas-layered` 延到 visible 後隔幀才掛，讓首繪與 431 層建立分兩幀。

### A2.（PLAUSIBLE）可見時建好、切走再回：GPU 紋理被回收＝整批 re-raster ＋ 動畫 loop 同幀恢復
- 背景分頁的 GPU tiles/textures 會被瀏覽器回收 → 切回時 431 個小合成層＋SVG 整批 re-raster（瀏覽器端行為，需 DevTools Performance 實測確認佔比）。
- 同一幀：`refreshFloatRunning` 的 visibilitychange handler 立即 `requestAnimationFrame(tickFloat)`（atlas.js:1883-1886，首 tick 節流必過＝寫 ~470 個 style/attr）＋ floating-items 60fps loop 同幀恢復（floating-items.js:1061-1063）。
- **修法**：visible→resume 首 tick 改 double-rAF 延遲；實測若 raster 是大頭，追加「待機定態期摘掉 `atlas-layered`、互動才掛回」。

### A3.（PLAUSIBLE）分頁凍結情境：timer 遲到到「切回那一刻」才進待機＝當著面跑完整 mount＋intro
- Chrome 凍結/激進節流下，3 分鐘 setTimeout 可能延到「解凍＝使用者切回」才執行；此時 `document.hidden` 已是 false → `instant=false` → 223KB atlas.js import/parse＋431 anchor 建構逐項量測＋SVG＋fade＋2.85s intro **全部當面跑**（idle-standby.js:313 時值太晚取；atlas.js:1106-1276、:2737-2745）。
- **修法**：enterStandby 記排程時間戳，實際 fire 遲到過多（> IDLE_TIMEOUT + 容差）→ 強制走 instant 定態（跳 fade/intro），或 defer 一輪 timer。

### A4.（CONFIRMED）切回後 0~10 秒：被節流的週期任務集中放行＝「頭幾秒斷續卡」
- atlas D 城市 relocate：guard 只擋「fire 當下 hidden」（atlas.js:972-973）、不延後可見後首發；且 relocate tween 的 onUpdate 每幀 `lastFloatTick = 0`（:1013/:960）＝**解除 30fps 節流達 1.2s、tickFloat 全速跑**。
- footer-scatter 10s shuffle：只 guard `offsetParent === null`（footer-scatter.js:409-414），不 guard hidden／待機——index 待機時 footer 可見＝照跑（BCR 讀＋最多 60 次 generatePlacement＋8 顆 tween）。
- index YT 卡 `setInterval(cycleLayout, 3000)` 完全無 hidden guard（index-yt-card.js:212、:253-261）。
- **修法**：dRelocate/rotateOnce 在 visible 時重置相位（延後首發幾秒）；footer-scatter shuffleAll 與 index-yt cycleLayout 各補 `if (document.hidden) return`（footer 另加 `body.idle-standby` guard）。

### A5.（PLAUSIBLE，mode3 限定放大器）hue loop 首幀 dispatch theme:changed
- colorTick 恢復首幀改 :root ~20 個 CSS 變數＋（距上次 >200ms 必成立）dispatch `theme:changed` → 7 個 listener（index-yt 整組 canvas 重繪等）擠進切回頭幾幀；overlay 7500 節點還掛著＝var invalidation 蓋兩棵樹（theme-toggle.js:191-203；index-yt-card.js:214-215）。
- **修法**：visible 後把 lastThemeDispatch 設為 now（跳過首幀 dispatch）。

### A6.（CONFIRMED，觸發條件窄）切回伴隨視窗幾何變化：resize 重掛＝單一超長 task
- resize debounce 後**同一個 task** 串行 `unmountStandbyAtlas()`（拆 7500 節點）＋ `mountStandbyAtlas(true)`（全量重建＋量測）（idle-standby.js:430-446）。只在換螢幕/DPI/投影等幾何真變的場景命中。
- **修法**：unmount 與 remount 之間隔一幀，或 remount 進 requestIdleCallback。

## 情境 B：回來動滑鼠 → 退出待機

### B1.（CONFIRMED，主因）退場收尾三件重活擠同一幀
- `requestAnimationFrame(() => requestAnimationFrame(() => { unmountStandbyAtlas(); ...ScrollTrigger.refresh(); }))`（idle-standby.js:386-393）＝**cleanupAtlas（drain 全部 cleanupFns＋killTweensOf）＋ `overlay.innerHTML=''`（同步拆 7500 節點、銷毀 431 合成層）＋ ScrollTrigger.refresh()（全頁 forced layout）同一個 callback**。
- 2026-06-30 的修法只把這批「延後兩幀」（:352-354 註解自證當年就卡過），總量沒切片——喚醒後第 3 幀左右必吃一根長幀，而使用者這時正在動滑鼠。
- **修法**：拆三拍——先 `overlay.style.display='none'`（脫離 render tree、便宜）→ 下一幀 cleanupAtlas → requestIdleCallback 內 `innerHTML=''` 與 `ScrollTrigger.refresh()` 分開跑。

### B2.（PLAUSIBLE）crossfade 首幀貴
- `pageContent.style.opacity='0'` 臨時 promote 整個 #page-content；同時 `fadeAtlasMain(0)` 對含 431 個 will-change 子層的 #atlas-main 做 group-opacity fade（祖先 opacity<1 → 建 render surface、每幀 flatten 431 子層）＝整段 DUR.reveal 期間 compositor 高負載（idle-standby.js:346-366）。
- **修法**：fadeAtlasMain(0) 前先 `stage.classList.remove('atlas-layered')`（退場淡出不需要逐 label 層）。

### B3.（PLAUSIBLE）reveal 幀偏重：body class 移除時 overlay 還掛著
- `body.classList.remove('idle-standby')` 在 7500 節點還在 render tree 時執行＝body 級 descendant selector 全文件 style recalc；同幀又做 logo reparent（idle-standby.js:372-374）。
- **修法**：同 B1 第一拍（先 display:none 再摘 class）順帶解掉。

### B4.（CONFIRMED，放大器）待機期間底頁動畫從未暫停
- floating-items 滿速 60fps 無 cap（只認 document.hidden，待機不觸發暫停；floating-items.js:1009-1066）、Lottie logo 每幀 SVG 更新、footer 10s shuffle——**被不透明 overlay 蓋住期間白跑**，退場幀還跟拆樹搶主執行緒。idle-standby.js 沒有任何底頁 pause 呼叫。
- **修法**：進/出待機廣播旗標，overlay 蓋住期間暫停 floating-items／footer-scatter（Lottie 可留）。

## 建議實測與實作順序
1. **實測定主因佔比**（DevTools Performance，實機）：①錄「背景進待機→切回」看首幀 Rasterize/Layerize 大小（分 A1 vs A2）；②錄「喚醒退出」看 double-rAF callback 的長 task（B1 幾乎必現）。
2. 實作順序建議：**A1**（hidden 不真 mount，純邏輯可 100% 推導、ROI 最高）→ **B1+B3**（退場拆三拍，一個改動蓋兩條）→ **B4/A4**（底頁暫停＋幾行 guard）→ 其餘依實測佔比。
3. 紅線：instant 定態的「切回來就已是待機」體驗要保留（A1 修法＝visible 後下一幀掛、視覺上幾乎等價）；atlas 頁自身的待機（不 mount overlay）路徑不動。
