========================================
SCCD 網站 — 請 IT 調大 Directus 上傳檔案大小上限
最後更新：2026-08-08
========================================

問題現象：
  後台上傳 PDF 檔案時，Directus 直接回這個錯誤、檔案存不進去：

    {
      "errors": [{
        "message": "Uploaded content is too large.",
        "extensions": { "code": "CONTENT_TOO_LARGE" }
      }]
    }

  （這是 Directus 本體擋下來的，不是 Apache——Apache 擋的話會是一頁 HTML 的 413 錯誤。
    代表檔案超過了 Directus 設定的單檔上傳上限 FILES_MAX_UPLOAD_SIZE。）


背景：
  我們要上傳的是掃描版舊刊物 / 作品集 PDF（例如「今日生活」歷年期刊），
  這類掃描檔常常一份就上百 MB，目前的上限擋住了。


請 IT 做：

1. SSH 進 Lightsail 主機，先看目前設的值（可能根本沒這行）：

     grep FILES_MAX_UPLOAD_SIZE /home/bitnami/directus-cms/.env

2. 編輯 .env，把上限設到 1 GB（若已有這行就改值，沒有就新增一行）：

     nano /home/bitnami/directus-cms/.env

   加上／改成：

     FILES_MAX_UPLOAD_SIZE="1gb"

   （Directus 11 這個變數吃人類可讀寫法，"1gb" 即可，不用換算 bytes。）

3. 重啟 Directus 生效：

     pm2 restart directus

4. Apache 反向代理的單一請求上限預設也是 1 GB，跟這個值剛好同一條線——
   接近 1 GB 的檔案會因為上傳封裝（multipart）的額外開銷先被 Apache 擋掉
   （症狀＝一頁 HTML 的 413 錯誤，跟 Directus 的 JSON 錯誤不同）。
   請順手把 Apache 上限放寬到 2 GB：在 Apache 設定（例如
   /opt/bitnami/apache/conf/bitnami/bitnami.conf 或對應 vhost）加：

     LimitRequestBody 2147483648

   然後重啟 Apache：

     sudo /opt/bitnami/ctlscript.sh restart apache


備註給 IT：
  - 後台目前只允許圖片與 PDF（FILES_MIME_TYPE_ALLOW_LIST 已設），這次不用動類型白名單。


改完檢查：
  1. pm2 status / pm2 logs directus —— 確認 Directus 有正常起來
  2. 後台重新整理，再上傳一次剛剛失敗的那份 PDF —— 應該能正常存進去
